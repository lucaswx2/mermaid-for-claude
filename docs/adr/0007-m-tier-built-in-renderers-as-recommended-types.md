# The four M-tier built-in renderers become recommended types; layouts, grammar subsets and the block edge list fixed

Wayfinder ticket #14 prototyped the four M-tier built-in renderers from ADR-0004 (gantt, quadrantChart, block, treemap) behind the same dispatcher, glyph table and text helpers as the S tier (ADR-0006), on branch `prototype/built-in-renderers`. The maintainer judged the rendered text in the shell (the same text the `Stop` `systemMessage` shows) and accepted all four as recommended types in the context line. Layouts: gantt is one row per task with sections as headings and a bar scaled to a time axis that spans the bar area, so the time scale compresses to whatever the width limit leaves after the label column; bar glyphs by state (`█` planned, `░` done, `▒` active), ` crit` after the bar, `◆` for a milestone, `┆` columns for `vert` markers with their titles under the chart, a legend for the states used. quadrantChart is a box split in four with the quadrant names in the corners, the y-axis labels above and below the box, the x-axis labels on a last row, `●` at the nearest cell with the label to the right, else to the left, else centred one row below or above inside the same half; a point with no room becomes a number with a legend under the chart. block is a grid of boxes with column spans, nested blocks as a box holding their own grid, `space` as a gap, block arrows as text with an arrow glyph, every shape drawn as a plain box, and edges listed under the grid as `A ──▶ B  label`. treemap is an indented tree with each node's value, its share of the parent (of the total for a root) and a bar scaled to that share. Rejected: drawing block edges on the grid (a text grid has no room for lines between boxes; a diagram that hinges on edges is a flowchart, which the baseline renderer draws); a quadrant scatter with more resolution than one cell per point (labels need the room more than the points do); a gantt row cap or wrapped task titles (titles are cut with `…`, rows stay one line each so the bars line up with the axis).

## Grammar subsets

- gantt: `title`; `dateFormat` with dayjs tokens `YYYY YY MM M DD D HH H hh h A a mm m ss s X x` (`MMM MMMM Do Q DDD DDDD S SS SSS Z ZZ` give a notice); `axisFormat` with d3 directives `%a %A %b %B %d %e %H %I %j %m %M %L %p %S %U %W %w %y %Y %Z %% %c %x %X`, default `%Y-%m-%d`, `%H:%M` when the date format carries no date; `tickInterval`, else the first step of a ladder from 1 second to 1 year whose labels do not overlap, the chart start always being the first tick; `excludes` / `includes` with `weekends`, weekday names and dates, `weekend friday|saturday`; `inclusiveEndDates`; `section`; task lines `title : [tags,] [id,] [start,] end` with tags `active done crit milestone vert`, start as a date or `after id [id...]`, end as a date, a duration (`ms s m h d w M y`, decimals allowed) or `until id [id...]`. Forward references resolve over passes and excluded days extend duration-based tasks day by day, both as mermaid does. Ignored: `todayMarker`, `topAxis`, `weekday`, `displayMode`, `click` / `href` / `call`. A first task without a start date, an unknown id, a duplicate id or an unparsable date gives a notice.
- quadrantChart: `title`, `x-axis left [--> right]`, `y-axis bottom [--> top]`, `quadrant-1..4 text`, `name[:::class]: [x, y]` with x and y in 0..1; styling after a point and `classDef` lines ignored.
- block: `block` / `block-beta`, `columns N|auto`, `id`, `id["label"]` in any bracket shape, `id:N`, `space[:N]`, `block[:id[:N]] ... end` with its own `columns`, `id<["label"]>(dir[, dir])` with `right left up down x y`, edges `a --> b`, `a --- b`, `a -- "x" --> b`, `a -->|x| b`; `style` / `classDef` / `class` lines ignored; HTML entities such as `&nbsp;` decoded. `columns auto` (or no `columns`) puts every block of the level on one row, as mermaid does; a block whose span does not fit the row wraps to the next row, where mermaid lets it overflow.
- treemap: `treemap` / `treemap-beta`, `title`, `"name"` sections, `"name": value` leaves, nesting by indentation, `:::class` after a name or a value; `classDef` lines ignored.

## Consequences

- The context line's recommended list grows from thirteen to seventeen types: the thirteen from ADR-0006 plus gantt, quadrantChart, block and treemap. No type is left saying "renders as simple text"; ER keeps "renders roughly"; requirementDiagram, C4, sankey, architecture and zenuml stay notice-only (ADR-0004).
- gantt titles are cut with `…` at the label column, at most 30% of the width limit; below about 32 columns gantt gives a notice, quadrantChart below about 27.
- Block edges are a list, not lines; the context line does not need to say so, since a model wanting arrows between boxes writes a flowchart.
- The four renderers were judged on shell output, not on the TUI; their samples join the S-tier samples in the TUI run of ticket #15.
- The bundle grows by about 19 KB; cold start per fire measured 360 to 420 ms on the maintainer's machine on a busy day, against 260 to 320 ms for the S tier alone, not measured in isolation.
- The prototype remains the reference implementation for the spec; the dispatcher's `TYPES` table now routes all twelve built-in types and keeps only the five notice-only types and `info` as notices.
